# الدور
أنت مهندس برمجيات أول (Senior Software Architect + Full-Stack Developer) ولديك خبرة في أنظمة ERP
وأنظمة نقاط البيع (POS) والفوترة الإلكترونية في السعودية ومصر. مطلوب منك تصميم وبناء نظام ERP
سحابي (SaaS) كامل، متعدد الموديولات، قابل للبيع كاشتراكات لشركات مختلفة، بجودة إنتاجية (Production-ready).

# 1) نظرة عامة على المنتج
- اسم المنتج: [اسم النظام]
- النوع: نظام ERP سحابي متعدد المستأجرين (Multi-tenant SaaS) + تطبيق نقطة بيع يعمل بدون إنترنت (Offline-first).
- الأسواق المستهدفة: المملكة العربية السعودية وجمهورية مصر العربية.
- الشرائح المستهدفة (Verticals):
  1. الكافيهات والمطاعم.
  2. الصيدليات (فرع واحد أو سلاسل).
  3. الشركات التجارية والخدمية (توزيع، جملة وتجزئة، شركات خدمات).
- اللغات: العربية (افتراضي، RTL كامل) والإنجليزية (LTR)، مع إمكانية التبديل لكل مستخدم.
- نموذج البيع: باقات اشتراك شهرية/سنوية، والعميل يفعّل الموديولات التي يحتاجها فقط (Module Licensing).

# 2) المبادئ المعمارية
- Multi-tenant: كل شركة (Tenant) معزولة تمامًا بياناتها (عمود tenant_id + Row Level Security في PostgreSQL،
  أو Schema لكل عميل للعملاء الكبار).
- كل شركة تملك: عدة فروع، عدة مخازن، عدة نقاط بيع، عدة عملات، عدة سنوات مالية.
- إعدادات الدولة (Country Pack): كل ما يخص الضرائب والفوترة الإلكترونية والرواتب والتقويم يتم تحميله
  حسب دولة الشركة (SA أو EG) عبر طبقة Localization منفصلة، بحيث يمكن إضافة دول الخليج لاحقًا بسهولة.
- إعدادات النشاط (Industry Pack): الكافيه / الصيدلية / الشركة تفعّل شاشات وحقول وتقارير خاصة بها
  فوق نفس النواة (Core).
- كل حركة مالية أو مخزنية تولّد قيد محاسبي تلقائي (Double-entry) بدون تدخل المستخدم.
- لا يتم حذف أي مستند مُرحّل؛ فقط إلغاء بمستند عكسي (Credit Note / Return) للحفاظ على سلامة الدفاتر.
- سجل تدقيق (Audit Log) لكل عملية إنشاء/تعديل/حذف/طباعة مع المستخدم والوقت والقيمة قبل وبعد.
- API-first: كل وظيفة متاحة عبر REST API موثّق (OpenAPI/Swagger) لاستخدامه من الويب والموبايل والتكاملات.

# 3) التقنيات المقترحة (يمكن تعديلها)
- Backend: [Node.js + NestJS + TypeScript] أو [Laravel] أو [Django] — اختر واحدًا والتزم به.
- Database: PostgreSQL + Redis (Cache/Queues).
- Frontend Web: React + TypeScript + Vite + TailwindCSS (دعم RTL) + مكتبة جداول متقدمة.
- POS: تطبيق ويب PWA أو Electron/Tauri لسطح المكتب، يعمل Offline بقاعدة محلية (IndexedDB/SQLite)
  ويزامن تلقائيًا عند عودة الإنترنت مع حل التعارضات.
- Mobile: React Native أو Flutter (تطبيق للمدير: تقارير لحظية، موافقات، مندوبين مبيعات).
- Jobs/Queues: BullMQ أو ما يعادله (إرسال الفواتير للجهات الضريبية، التقارير الثقيلة، الإشعارات).
- Storage: S3-compatible للمرفقات والصور.
- Deployment: Docker + Docker Compose للتطوير، و CI/CD، مع استضافة يُفضَّل أن تكون داخل السعودية
  لعملاء السعودية (متطلبات حماية البيانات PDPL).
- Auth: JWT + Refresh Tokens، مع دعم 2FA.

# 4) الموديولات الأساسية (Core Modules)

## 4.1 الإعدادات والإدارة (Admin & Setup)
- إنشاء الشركة: الاسم عربي/إنجليزي، السجل التجاري، الرقم الضريبي، العنوان الوطني (للسعودية)، الشعار.
- الفروع، المخازن، مراكز التكلفة، السنوات والفترات المالية (فتح/إغلاق فترة).
- المستخدمون والأدوار والصلاحيات (RBAC) على مستوى: الموديول، الشاشة، العملية (عرض/إضافة/تعديل/حذف/طباعة/اعتماد)،
  والفرع والمخزن، مع حدود مثل: أقصى نسبة خصم للكاشير.
- سلاسل الترقيم للمستندات لكل فرع، قوالب الطباعة (A4 + إيصال حراري 80mm/58mm) قابلة للتخصيص.
- النسخ الاحتياطي والاستيراد/التصدير من Excel لكل البيانات الأساسية.

## 4.2 المحاسبة العامة (Accounting / GL)
- شجرة حسابات متعددة المستويات مع قالب جاهز لكل دولة ولكل نشاط.
- القيود اليومية اليدوية والآلية، القيود المتكررة، القيود العكسية.
- الخزائن والبنوك، سندات القبض والصرف، الشيكات (تحت التحصيل / مرتدة)، التسويات البنكية.
- العملات المتعددة وفروق العملة.
- مراكز التكلفة والمشاريع.
- إقفال السنة المالية وترحيل الأرصدة.
- التقارير: ميزان المراجعة، قائمة الدخل، الميزانية العمومية، التدفقات النقدية، دفتر الأستاذ،
  كشوف الحسابات، أعمار الديون، تقرير ضريبة القيمة المضافة (الإقرار الضريبي).

## 4.3 المبيعات (Sales)
- عروض الأسعار ← أوامر البيع ← إذن صرف/تسليم ← الفاتورة ← التحصيل.
- مرتجعات المبيعات (إشعار دائن) وإشعارات المدين.
- قوائم أسعار متعددة، عروض وخصومات (نسبة/مبلغ/اشترِ X واحصل على Y)، حد ائتماني للعميل.
- المندوبين والعمولات والمناطق.
- الفاتورة الضريبية والفاتورة المبسطة متوافقة مع الفوترة الإلكترونية (انظر القسم 6).

## 4.4 المشتريات (Purchasing)
- طلب شراء ← أمر شراء ← استلام ← فاتورة مورد ← سداد.
- مرتجعات المشتريات، تكاليف الاستيراد الإضافية (Landed Cost) وتوزيعها على الأصناف.
- تقييم الموردين واعتمادات أوامر الشراء حسب المبلغ.

## 4.5 المخزون (Inventory)
- الأصناف: كود، باركود (متعدد)، وحدات متعددة بمعاملات تحويل، صور، تصنيفات، أصناف خدمية.
- تتبع بالتشغيلة (Batch/Lot) وتاريخ الصلاحية والرقم التسلسلي (Serial).
- التحويلات بين المخازن والفروع، الجرد الدوري والمستمر، التسويات، التالف والهالك.
- طرق التكلفة: المتوسط المرجح (افتراضي) و FIFO، وصرف FEFO للأصناف ذات الصلاحية.
- حد الطلب وتنبيهات النواقص واقتراح أوامر الشراء آليًا.
- طباعة ملصقات الباركود.

## 4.6 نقطة البيع (POS)
- واجهة لمس سريعة، بحث بالباركود والاسم، يعمل Offline.
- فتح/إغلاق الوردية (Shift) وعهدة الكاشير، تقرير X و Z، جرد النقدية.
- طرق دفع متعددة في نفس الفاتورة (كاش/شبكة/محافظ/آجل)، تعليق الفاتورة واسترجاعها، المرتجع من نقطة البيع.
- دعم أجهزة: طابعة حرارية، درج نقدية، قارئ باركود، شاشة عميل، ميزان باركود، أجهزة الدفع (mada/فيزا).
- إصدار QR الفاتورة المبسطة لكل إيصال (السعودية) والإيصال الإلكتروني (مصر).

## 4.7 العملاء والـ CRM
- ملف العميل، تاريخ المعاملات، نقاط الولاء والكوبونات وبطاقات الهدايا.
- العملاء المحتملين، المتابعات، الحملات عبر SMS/واتساب.

## 4.8 الموارد البشرية والرواتب (HR & Payroll)
- ملفات الموظفين، العقود، المستندات (الإقامة/الجواز مع تنبيهات انتهاء)، الهيكل التنظيمي.
- الحضور والانصراف (ربط بأجهزة البصمة أو تطبيق موبايل بالموقع الجغرافي)، الورديات، الإجازات، الأذونات.
- مسير الرواتب: البدلات، الاستقطاعات، السلف، الإضافي، الجزاءات.
- السعودية: اشتراكات التأمينات الاجتماعية (GOSI)، ملف حماية الأجور (WPS/مُدد)، مكافأة نهاية الخدمة
  حسب نظام العمل السعودي، نسب السعودة.
- مصر: التأمينات الاجتماعية حسب القانون 148 لسنة 2019، ضريبة كسب العمل بالشرائح السارية، مكافأة نهاية الخدمة.
- **مهم:** كل النسب والشرائح تكون جداول إعدادات قابلة للتعديل وليست مكتوبة داخل الكود.

## 4.9 الأصول الثابتة (Fixed Assets)
- سجل الأصول، الإهلاك (قسط ثابت/متناقص) بقيد آلي شهري، الاستبعاد والبيع، الصيانة.

## 4.10 التقارير ولوحات التحكم (Reports & BI)
- لوحة تحكم لحظية: المبيعات اليوم، أفضل الأصناف، الأرباح، النقدية، النواقص، الأصناف قريبة الانتهاء.
- منشئ تقارير مرن مع فلاتر وتجميع وتصدير PDF/Excel، وجدولة إرسال التقارير بالبريد.
- مقارنة الفروع والفترات.

# 5) حزم الأنشطة (Industry Packs)

## 5.1 الكافيهات والمطاعم
- إدارة الصالة: خريطة الطاولات، فتح الطاولة، نقل/دمج/تقسيم الفاتورة، عدد الأفراد.
- أنواع الطلب: صالة، تيك أواي، توصيل، Drive-thru.
- الإضافات والتعديلات (Modifiers) مثل: الحجم، نوع الحليب، السكر، الإضافات المدفوعة.
- الوصفات (Recipe/BOM): خصم المكونات الخام من المخزون تلقائيًا عند البيع وحساب تكلفة الكوب/الطبق.
- شاشة المطبخ/الباريستا (KDS) وطابعات المطبخ حسب القسم.
- كومبو ووجبات، أوقات عروض (Happy Hour)، قائمة رقمية بـ QR وطلب ذاتي من الطاولة.
- التكامل مع تطبيقات التوصيل: السعودية (هنقرستيشن، جاهز، مرسول، تويو)، مصر (طلبات، مرسول، بريد فاست) — عبر طبقة Integration قابلة للتوسعة.
- تقارير: تكلفة المواد وهامش الربح لكل صنف، الهدر، أداء الموظفين، ساعات الذروة.

## 5.2 الصيدليات
- دليل أدوية: الاسم التجاري، المادة الفعالة، الشكل الدوائي، التركيز، الشركة المصنعة، سعر الجمهور الرسمي.
- البحث بالمادة الفعالة واقتراح البدائل.
- إلزامية التشغيلة وتاريخ الصلاحية لكل حركة، صرف FEFO تلقائي، تنبيهات قبل الانتهاء بفترة قابلة للضبط،
  ومرتجعات الأدوية منتهية الصلاحية للمورد.
- البيع بالعلبة والشريط والقرص (وحدات متعددة).
- الروشتات (الوصفات الطبية): ربطها بالعميل والطبيب، الأدوية المراقبة/المخدرة بسجل خاص وصلاحيات مشددة.
- التأمين الطبي: شركات التأمين، نسب التحمل، المطالبات الشهرية.
- السعودية: التكامل مع نظام "رصد" للتتبع الدوائي التابع لهيئة الغذاء والدواء (SFDA) — مسح DataMatrix وإبلاغ الاستلام والصرف.
- مصر: الالتزام بأسعار هيئة الدواء المصرية (EDA) وتحديث قوائم الأسعار.
- تقارير: الأصناف الراكدة، قريبة الانتهاء، النواقص، الأرباح حسب الشركة المصنعة.

## 5.3 الشركات التجارية والخدمية
- التوزيع والمندوبين: خطوط سير، تطبيق مندوب (طلبات، تحصيل، مرتجعات) يعمل Offline.
- البيع بالجملة والتجزئة بقوائم أسعار مختلفة.
- إدارة المشاريع والعقود والفوترة على مراحل (للشركات الخدمية)، وتتبع ساعات العمل.
- التصنيع الخفيف (اختياري لاحقًا): أوامر إنتاج وقوائم مواد.

# 6) الامتثال الضريبي والفوترة الإلكترونية (إلزامي)

## 6.1 السعودية — هيئة الزكاة والضريبة والجمارك (ZATCA)
- ضريبة القيمة المضافة 15% (قابلة للتعديل من الإعدادات)، مع دعم الأصناف المعفاة والخاضعة لنسبة صفر.
- الفوترة الإلكترونية "فاتورة" المرحلة الأولى (الإصدار) والمرحلة الثانية (الربط والتكامل):
  - إصدار الفاتورة بصيغة XML وفق UBL 2.1 ومواصفات ZATCA.
  - الفاتورة الضريبية (B2B) تُرسل للاعتماد (Clearance) قبل تسليمها للعميل.
  - الفاتورة المبسطة (B2C) تُرسل للإبلاغ (Reporting) خلال 24 ساعة.
  - توليد QR Code بترميز TLV، الختم التشفيري (Cryptographic Stamp)، الـ Hash التسلسلي (PIH) وعداد الفواتير (ICV) و UUID.
  - إدارة شهادات الأجهزة (CSR / Compliance CSID / Production CSID) لكل فرع أو نقطة بيع، وبيئات Sandbox/Simulation/Production.
  - طابور إعادة المحاولة للفواتير الفاشلة وعرض حالة كل فاتورة (مقبولة/مرفوضة/تحذيرات).
- دعم التاريخ الهجري بجانب الميلادي، والعملة الريال السعودي (SAR).

## 6.2 مصر — مصلحة الضرائب المصرية (ETA)
- ضريبة القيمة المضافة 14% (قابلة للتعديل)، وضريبة الجدول، وخصم المنبع.
- منظومة الفاتورة الإلكترونية (B2B): إرسال الفواتير بصيغة JSON عبر API المنظومة، التوقيع الإلكتروني
  (USB Token / HSM)، أكواد الأصناف (GS1 / EGS)، أكواد أنواع الأنشطة، متابعة حالة الفاتورة (Valid/Invalid) والإلغاء والرفض.
- منظومة الإيصال الإلكتروني (B2C) لنقاط البيع: تسجيل نقاط البيع، إرسال الإيصالات، طباعة QR على الإيصال.
- العملة الجنيه المصري (EGP).

**ملاحظة للتنفيذ:** المواصفات والنسب التنظيمية تتغير؛ اجعل كل ذلك في إعدادات وجداول، وارجع إلى
الوثائق الرسمية الحالية لـ ZATCA و ETA قبل التنفيذ، واكتب اختبارات لكل حالة.

# 7) التكاملات (Integrations)
- الدفع: السعودية (mada، Apple Pay، STC Pay، أجهزة نقاط البيع، بوابات مثل Moyasar/HyperPay/Tap)،
  مصر (فوري، InstaPay، المحافظ الإلكترونية، Paymob، أجهزة POS البنكية).
- الرسائل: SMS وواتساب بيزنس (إرسال الفاتورة PDF للعميل، تذكير بالمستحقات).
- البريد الإلكتروني.
- أجهزة البصمة.
- Webhooks و API Keys لكل عميل لربط أنظمته.

# 8) إدارة الاشتراكات والبيع (لصاحب النظام — Super Admin)
- لوحة تحكم لصاحب النظام: إدارة العملاء (Tenants)، الباقات، الموديولات المفعّلة، عدد الفروع والمستخدمين ونقاط البيع.
- باقات مقترحة: [أساسية / احترافية / مؤسسات] + إضافات مدفوعة (موديول، فرع إضافي، نقطة بيع إضافية).
- فترة تجريبية مجانية، تجديد تلقائي، فوترة العملاء نفسها، إيقاف الحساب عند عدم السداد مع فترة سماح.
- معالج إعداد (Onboarding Wizard): اختيار الدولة والنشاط ← إنشاء شجرة الحسابات والإعدادات الافتراضية ← استيراد الأصناف من Excel ← جاهز للبيع.
- وضع Demo ببيانات تجريبية لكل نشاط لاستخدامه في العروض التسويقية.
- نظام تذاكر دعم فني داخل النظام وصفحة تحديثات (Changelog).

# 9) المتطلبات غير الوظيفية
- الأداء: إصدار فاتورة POS في أقل من ثانية، والشاشات تُحمَّل في أقل من ثانيتين، مع Pagination و Indexes مناسبة.
- الأمان: OWASP Top 10، تشفير كلمات المرور (bcrypt/argon2)، HTTPS فقط، Rate Limiting، تشفير البيانات الحساسة، صلاحيات على مستوى الصف.
- حماية البيانات: الالتزام بنظام حماية البيانات الشخصية السعودي (PDPL) وقانون حماية البيانات المصري رقم 151 لسنة 2020.
- النسخ الاحتياطي اليومي التلقائي مع إمكانية الاستعادة.
- قابلية التوسع أفقيًا، ومراقبة وسجلات (Logging/Monitoring).
- الدقة المالية: استخدم Decimal وليس Float لكل المبالغ، وقواعد تقريب واضحة لكل دولة.
- إمكانية الوصول وتجربة مستخدم بسيطة لموظف غير تقني.

- المرحلة 0: التصميم — مخطط ERD كامل، هيكل المشروع، تعريف الـ API، تصميم الشاشات الرئيسية (Wireframes).
- المرحلة 1 (MVP): Multi-tenant + المستخدمين والصلاحيات + الأصناف والمخزون + المبيعات والمشتريات + POS + المحاسبة الأساسية + VAT + الفوترة الإلكترونية للسعودية.
- المرحلة 2: حزمة الكافيهات (طاولات، Modifiers، وصفات، KDS) + حزمة الصيدليات (تشغيلات وصلاحية، دليل أدوية، روشتات) + الفوترة الإلكترونية والإيصال الإلكتروني لمصر.
- المرحلة 3: الموارد البشرية والرواتب + الأصول الثابتة + CRM والولاء.
- المرحلة 4: تطبيق الموبايل + تكاملات التوصيل والدفع + لوحة Super Admin والاشتراكات + BI متقدم.
- المرحلة 5: التأمين الطبي، رصد، المندوبين، التصنيع الخفيف.

## نصائح لاستخدام البرومت
- **ابدأ بالمرحلة 0 فقط** وراجع التصميم قبل الكود؛ المشروع كبير ولو اتبنى مرة واحدة هيطلع ضعيف.
- **حدد التقنيات** في القسم 3 قبل ما تبعته (مثلًا NestJS + React) عشان النتيجة تكون ثابتة.
- **ابعت برومت منفصل لكل مرحلة** وذكّر الأداة بالقسم الخاص بيها من البرومت ده.
- **راجع مواصفات ZATCA و ETA الرسمية الحالية** لأنها بتتحدث، والنسب (الضريبة، التأمينات، الشرائح) لازم تتأكد منها قبل الإطلاق.
